## 总体思路概览

“Snowpipe for Azure”这部分内容讲的是：如何在 Azure Blob Storage 上配置事件驱动的 Snowpipe，让上传到容器的新 CSV 文件可以自动、近实时地加载到 Snowflake 表中。核心对象包括 Storage Integration、外部 Stage、Notification Integration（对接 Azure Storage Queue）以及使用 auto_ingest 的 Pipe。[^1][^2][^3]

## 步骤一：创建 Storage Integration 与 Stage

- 先在 Snowflake 中专门建一个库（如 SNOWPIPE），然后创建 Azure Storage Integration，用于安全访问 Blob 容器：
    - 指定 TYPE=EXTERNAL_STAGE、STORAGE_PROVIDER=AZURE、ENABLED=TRUE。
    - 设置 AZURE_TENANT_ID 和 STORAGE_ALLOWED_LOCATIONS（指向具体容器 URL）。[^1]
- 创建文件格式对象（CSV）和 Stage：
    - FILE FORMAT 里指定 TYPE=CSV、FIELD_DELIMITER=','、SKIP_HEADER=1 等。
    - STAGE 上绑定 STORAGE_INTEGRATION 和对应的容器 URL，例如 https://your-container-url。
    - 用 LIST snowpipe.public.stageazure 验证 Snowflake 能列出容器里的文件。[^1]


## 步骤二：创建 Notification Integration 对接 Azure 队列

- 在 Snowflake 中创建 Notification Integration，用于接收 Azure Storage Queue 的事件消息：
    - TYPE=QUEUE，NOTIFICATION_PROVIDER=AZURE_STORAGE_QUEUE。
    - 指定 AZURE_STORAGE_QUEUE_PRIMARY_URI（队列 URL）和同一个 AZURE_TENANT_ID。
    - 使用 DESC NOTIFICATION INTEGRATION snowpipeevent 查看需要在 Azure 端配置的服务主体信息和权限。[^3]
- 在 Azure 端，将 Blob 容器的“新增/修改 Blob”事件发往 Storage Queue，使每次上传文件都会产生一条队列消息，从而触发 Snowpipe。[^3]


## 步骤三：创建目标表并验证 COPY 语句

- 先通过 Stage 查询 CSV 列序号（SELECT 1…20 FROM stageazure）确认列顺序和数量。[^2]
- 创建目标表 snowpipe.public.happiness，列结构对应 world-happiness-report-2021.csv 中的 20 列（如 country_name、regional_indicator、ladder_score 等，并配置合适的 NUMBER(4,3)/NUMBER(5,3)/VARCHAR）。[^2]
- 使用普通 COPY 测试一次批量加载：
    - COPY INTO happiness FROM snowpipe.public.stageazure;
    - SELECT * FROM snowpipe.public.happiness 校验数据正确，再 TRUNCATE TABLE 为 Snowpipe 自动加载做准备。[^2]


## 步骤四：创建 Snowpipe（auto_ingest + Azure 通知）

- 定义 Pipe，将 Notification Integration 与 Stage、目标表串联起来：
    - create pipe azurepipe auto_ingest = true integration = SNOWPIPEEVENT as copy into snowpipe.public.happiness from snowpipe.public.stageazure;[^2]
    - 这里 integration 引用的就是前面创建的 Notification Integration snowpipeevent。
- 创建后可以通过：
    - SELECT SYSTEM\$PIPE_STATUS('AZUREPIPE') 查看 Snowpipe 状态和 pendingFileCount 等运行信息。[^2]


## 运行效果与使用方式

配置完成后，只要有新的 CSV 文件被上传到绑定的 Azure Blob 容器且触发到对应 Storage Queue，Snowpipe 就会自动执行 COPY INTO，将这些文件加载进 snowpipe.public.happiness 表，无需手动跑作业。日常运维可以通过 PIPE_STATUS、COPY_HISTORY 等视图监控加载情况，并在需要时手动 TRUNCATE 或重新 COPY。[^3][^1][^2]
