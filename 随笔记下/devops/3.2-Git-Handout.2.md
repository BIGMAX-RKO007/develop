# 继续

以下为《3.2 Git Handout.pdf》的续译（含仓库初始化、分支与合并请求、Git 在 DevOps 中的作用，以及命令速查表和最佳实践）：

***

Git 仓库的设置 - 远程仓库

- 在 Gitlab、GitHub 等平台注册账号，创建新仓库。公司也通常有自建 Git 服务器。
- 仓库可选择公开或私有（企业多为私有，开源多为公开）。

***

Git 仓库的设置 - 本地仓库

- 须在本地安装 Git 客户端（GUI 图形或 CLI 命令行）。
- 首次克隆仓库需在命令行执行 git clone（或用界面工具）。
- 需先配置 SSH 公钥，将公钥添加到 Git 平台，方可安全认证推送（push/pull）。

***

本地项目初始化

- 如已有本地项目，可用 git init 初始化为 git 仓库，然后配置远程仓库（git remote add origin ...），即可推送至平台。

***

分支（Branch）的概念

- 分支提升协作效率。新建仓库默认有 main（或 master）主分支。
- 开发者可为新功能、bug 修复创建临时分支，各自独立开发，不影响主分支。
- 常见分支命名：main、dev、feature、bugfix，推荐一功能/bug 一分支。
- 分支开发完成后，合并回主分支，主分支应始终保持稳定以便随时上线。

***

合并请求（Merge Request/Pull Request）

- 合并请求（MR/PR）是分支合并的提议和流程。
- 最佳实践：他人审核合并（代码评审），可批准或拒绝。

***

DevOps 工程师为什么要熟悉 Git

- 1. 基础用例：基础设施即代码（IaC），脚本与配置随代码用 Git 管理，具备审计和协作基础。
- 2. 自动化脚本：如用 Python 编写的自动化工具，代码同样可用 Git 管理。
- 3. CI/CD 自动化构建与发布：集成编译、测试、部署流程全与 Git 关联，需熟练掌握常用命令如指定 commit、检查分支变更等。

***

Git 命令速查表（部分）

- git init 初始化仓库
- git clone 克隆远程仓库
- git add / git commit / git status / git log / git diff 各类变更追加、提交、状态及差异比对
- git branch / git checkout -b / git merge 分支操作与合并
- git reset / git revert / git commit --amend / git rebase 撤销修改、历史重写
- git remote add / git fetch / git pull / git push 远程仓库管理与同步
- ...还有其他参数用法详见讲义最后附录

***

最佳实践

- 写清晰有意义的提交信息，单一变更分开提交，只提交相关内容。
- 使用 git config 明确作者信息。
- feature/bugfix 分支及时同步主分支，频繁 pull 避免大规模冲突。分支不宜拖太久。
- 不要直接向主分支 push，--force 慎用（最好只在自己分支用，绝不在 master 上用）。
- 新功能/修复请新开分支，推荐前缀 feature/xxx、bugfix/xxx。
- 借助合并请求做代码评审。
- .gitignore 忽略编辑器专属文件/目录、构建文件夹等。
