# 继续

补充《10.2 Kubernetes Handout.pdf》的剩余内容详细翻译，聚焦 K8s多集群、灰度发布、Helm Chart、Operator、DevOps微服务部署、全流程命令实践与生产安全最佳实践：

***

Kubernetes 多节点/多集群扩展与弹性实践

- 集群横向扩展
    - 新建物理（或虚拟）服务器，安装 Control Plane/Worker 进程，运行 k8s join 命令即可接入集群。
    - 集群计算和高可用性随着节点数量线性提升，配合负载均衡与多副本实现零宕机。

***

Minikube 本地开发与 kubectl 命令实践

- Minikube 单机本地测试，适合开发调试。支持 Docker 或虚拟机模拟集群环境。
- kubectl 核心命令：
    - get、describe、apply、delete、edit、logs、exec、port-forward、scale、rollout、top、create、config（速查详见附录）
    - YAML 配置文件自动化管理所有资源，推荐纳入 Git 版本控制。

***

K8s YAML 配置与模板化管理

- Manifest 配置结构:
    - metadata：资源元数据，包含名称、标签、注释等
    - spec：描述期望状态与参数，随类型变化
    - status：当前运行状态，自动生成
    - 所有 YAML 严格缩进，建议 Editor 加插件强化校验
    - 建议所有配置文件集中 Git 管理，提升运维效率和团队协作。
- Label/Selector 机制:
    - 通过 key:value 分组/筛选资源，Service 通过 selector 选择目标 Pod，对多版本灰度发布和分流极其重要

***

Service 类型和 Ingress 路由

- Service 分类：ClusterIP（集群内）、NodePort（集群外端口映射）、LoadBalancer（云厂商负载均衡）、Headless（数据库/有状态服务）
- 生产入口建议统一用 Ingress/负载均衡，安全且灵活
- Ingress Controller 多厂商/开源版本，推荐 NGINX/Cloud Native LB 实现 TLS、路由、灰度、统一外部流量入口

***

持久化卷与 StatefulSet/Deployment 区别

- 持久化推荐用远程/云存储（AWS EBS, NFS, Ceph 等），自动 Provision + PVC/StorageClass 动态绑定
- 无状态服务用 Deployment，数据无存储/随 Pod 自由消亡
- 有状态服务用 StatefulSet，数据独有且随副本唯一，保证主从一致与持久化

***

Helm Chart 包管理与模板化部署

- 所有服务/应用配置建议 Helm Chart 模板化，values.yaml 动态参数实现多环境自动差异部署
- 企业建议架设 Nexus/仓库管理 Helm Chart 公私分区，与 ArtifactHub/官方 Chart同步/定制分发
- Helmfile 支持多 Chart 一键管理、升级、回滚与批量运维

***

Kubernetes Operator 与自定义资源管理

- Operator 基于 CRD 机制，实现如数据库主从、备份、自动自愈等自动化运维
- 所有自动化数据库、消息队列（如 MySQL Operator、Kafka Operator）推荐用官方 Operator集成

***

RBAC 授权和 ServiceAccount 实践

- RBAC 推荐生产务必启用，ClusterRole/Role 分权分责，RoleBinding 绑定具体用户或服务账号。
- ServiceAccount 专供自动化脚本、工具（如 Jenkins/Prometheus）基于权限执行 K8s 任务，避免全局密钥滥用

***

微服务架构 DevOps 部署任务流程

1. 准备集群与网络环境
2. 部署所需第三方服务
3. 创建 Secret/ConfigMap 以注入敏感与动态配置
4. 为各微服务分别编写 Deployment/Service/Ingress YAML
5. 通过 Helm Chart 进行批量模板化部署，CI/CD自动化推进

***

Kubernetes 生产最佳实践总结

- 每个镜像显式版本，绝不使用 latest
- 所有容器均配 Liveness/Readiness 探针，业务宕机自动自愈
- 设置资源限额 requests/limits，防止单点拖垮全局
- 生产环境禁用 NodePort，互联网流量只经 Ingress/负载均衡统一入口
- 所有关键服务多副本部署、节点多台冗余防止单点宕机
- 全部资源加标签/命名空间分组，方便权限分层与自动化管理
- 密钥绝不写入镜像，全部用 Secret/ConfigMap 管理
- 所有第三方库/镜像定期代码扫描（CI/CD集成漏洞自动检测）
- 容器内部绝不以 root 权限运行
- 集群所有组件定期升级，自动化零宕机滚动发布
