# 16.2-Prometheus-Handout.pdf

以下是《16.2 Prometheus Handout.pdf》的详细中文翻译（按章节汇总，体系结构+部署+应用监控+告警+最佳实践）：

***

**什么是 Prometheus？为何需要监控？**

- Prometheus 是开源监控与告警工具，广泛应用于云原生与分布式系统，活跃社区支持。
- 它通过“抓取”目标的 HTTP /metrics 端点，收集、存储、整理所有度量（metrics）数据，形成时序数据。
- 大规模容器/微服务/基础设施环境只有统一监控体系才能保障可视性与持续健康。

***

**监控场景与价值**

- 有数百/数千容器、基础设施、应用，人工排查极其低效，需要可见性、持续监控、自动告警。
- 监控工具可帮助排查异常，节省人力与时间。
- 应用前端报错，可能根源在后端某组件，监控能迅速定位根因。

***

**Prometheus 架构核心组件**

1. **Prometheus Server**
    - 主体，负责抓取（scrape）和存储数据，支持 PromQL 查询。
    - 通过 HTTP 轮询目标端点（pull）。
2. **目标与度量（Targets \& Metrics）**
    - 如 Linux/Windows 物理机、数据库、中间件、微服务。
    - 采集 CPU、内存、磁盘等资源指标，及服务级请求数、异常数量等。
3. **Exporter 外部采集器**
    - 三方服务有的默认暴露 /metrics，如 Redis、Linux 用 node_exporter。
    - 部分需用 exporter “转化”原有指标为 Prometheus 格式，供 Prometheus Server 抓取。
4. **自定义业务指标采集**
    - 官方/社区 Prometheus Client Library 支持多语言（Go/Python/JavaScript等）
    - 应用通过库以 Counter、Gauge、Histogram、Summary 等类型暴露业务核心指标。

***

**Pull vs Push 模型**

- Prometheus 典型为“拉取”模式（pull），主动 HTTP 轮询各端点。
- CloudWatch/NewRelic 等是“推送”模式（push），需额外 agent。
- Pushgateway 是 Prometheus 特殊中介，仅少部分 batch Job 场景用。

***

**Alertmanager 告警体系**

- Prometheus 独立配置告警规则，异常触发立即推送至 Alertmanager。
- Alertmanager 实现告警分组、去重、多通道通知（邮件、Slack、钉钉等，配置 receivers）。
- 邮件告警配置可自定义告警内容、收件人等。

***

**Prometheus 数据存储与查询**

- 默认本地高效时序数据库，也可扩展远程存储（如 S3/GCS）。
- 支持 PromQL 查询（如 HTTP 5xx 错误，CPU 曲线等），推荐 Grafana 联合可视化。

***

**配置与 YAML 文件实例**

- prometheus.yaml 管理抓取目标、抓取时间间隔、告警规则等。
- 典型结构：

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s
rule_files:
  - "first.rules"
  - "second.rules"
scrape_configs:
  - job_name: prometheus
    static_configs:
      - targets: ['localhost:9090']
  - job_name: node_exporter
    scrape_interval: 1m
    static_configs:
      - targets: ['localhost:9100']
```


***

**可视化与聚合**

- Grafana 开箱即用，支持多数据源可视化，dashboard/panel/rows 结构灵活可扩展。
- Kubernetes 资源可自动聚合 CPU、内存、网络等关键指标，应用层可按需求自建 dashboard。

***

**告警规则实战与 Alertmanager 配置**

- 配置 example：
    - CPU usage 大于 50%
    - Pod 启动失败
    - 邮件通道管理告警分组、收件人
- Alertmanager yaml 配置支持多场景/多收件人/多组分发。

***

**三方服务与自研微服务监控**

- Redis/Node/数据库等常用 exporter 实现底层运行数据监控。
- 无 exporter 时，用 Client Library 业务代码级暴露 /metrics，由 Prometheus 配套 ServiceMonitor 自动采集、Grafana可视化。

***

**性能与扩展特性**

- Prometheus 单机可靠强悍，易用性好，但原生扩展和高可用有门槛。
- 支持联邦查询（Prometheus Federation），适配千万节点与多数据中心场景。

***

**生产最佳实践**

- 官方职责/标签命名规范：https://prometheus.io/docs/practices/naming/
- 代码层指标暴露：https://prometheus.io/docs/practices/instrumentation/
- Grafana dashboard/告警案例社区库推荐
- 所有配置/YAML/告警与业务指标均应纳管 Git、文档化管理，支持团队协作与运维自动化。
