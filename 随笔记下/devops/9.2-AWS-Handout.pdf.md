***

AWS 服务基础

AWS 简介

- AWS 即 Amazon Web Services
- 目前全球最流行的云平台，服务极为丰富，涵盖:
    - 分析、应用集成、成本管理、区块链、业务应用、计算、容器、数据库、开发者工具、终端用户计算、前端与移动开发、物联网、游戏开发、网络等

重要控制台功能:

- 可快捷查看 VPC（虚拟私有云）、EC2（云服务器）、组织管理、健康监控、弹性 Beanstalk、IAM（身份和权限）、成本可视化。

***

AWS 账号与服务作用范围

- AWS 中资源的作用域分为三层：“全局（Global）”、“区域（Region）”以及“可用区（AZ，Availability Zone）”。
- 如：IAM 用户属全局，某些资源（S3、VPC）属于区域，EC2/EBS/RDS 属于区级。

***

AWS 账号注册流程

1. 注册流程：访问 AWS 官网，点击创建账号；可使用公司邮箱便于归档和权限管控。
2. 需填写付款信息（银行卡、账单地址），验证后可正式开通。中国和印度用户额外涉及 CVV 验证和小额支付验证。

- 无有效付款方式将无法完成注册流程。

***

AWS 免费套餐

- 新用户 1 年享多项基本服务免费额度，如：
    - EC2 小型云主机每月 750 小时
    - S3 对象存储 5GB
    - RDS 托管数据库每月 750 小时
- 部分服务不涵盖在免费范围，临时用完后请记得及时释放资源。

***

核心服务汇总

- 身份与访问管理（IAM）
- 虚拟私有云（VPC）、网络与安全
- EC2 云服务器
- 数据库、存储、容器与自动化等

***

身份与访问管理（IAM）

- 主要用于配置谁可以访问哪些资源 :
    - 创建并管理用户/组
    - 分配权限策略（policy）
    - ROOT 用户默认有完全管理员权限，建议日常用新建 admin 权限账户管理。
    - 人类用户与系统用户（如 Jenkins 部署权限用 Service User）分开管理。推荐通过分组、分策略控制批量权限。
- IAM 角色（Role）可实现 AWS 服务间、应用间安全互信。角色可被服务动态“扮演”，常用于 ECS、EC2、EKS 服务自身访问其他云资源。

***

区域与可用区

- 所有云服务都部署在物理数据中心，数据中心以“Region（区域）”为分布单位。每个 Region 下有若干可用区（AZ），即物理独立的数据中心机房。
- 每项云服务需指定 Region，不同数据中心价格/位置/资源完备度不同。
- 常用如：美国东部（N.Virginia）、东京、法兰克福、伦敦等

***

VPC 虚拟私有云原理

- VPC 是 AWS 上“独立的内网”，等价于本地物理机房的网络环境。所有资源必须运行在 VPC 下。每个 Region 都有默认 VPC，可自定义多 VPC。

***

子网与内网

- 子网（Subnet）就是 VPC 内部的 IP 地址分段。每个可用区可以有一个或多个子网
- 可根据网络安全配置，灵活设置私有或公有子网。公有子网可直接访问外部互联网；私有子网仅本地访问或通过 NAT 路由。

***

子网与安全组

- 子网内部流量基于防火墙、安全组（Security Group）、NACL（网络 ACL）细粒度控制。可为每台云主机单独配置安全组，细致管控出入端口和 IP。

***

CIDR Block 说明与划分

- CIDR 即无类域间路由，决定 IP 分段和网络划分粒度（如 172.31.0.0/16）。
- 可用 IP 量公式：2^(32-子网掩码位数)；拆分、合并子网可用辅助工具。

***

启动/配置 EC2 实例流程

1. 选择操作系统镜像（如 Ubuntu、Amazon Linux）
2. 设置云主机性能、存储
3. 映射到 VPC、指定子网、安全组
4. 配置 SSH 密钥对
5. 添加描述性标签
6. 创建与连通性测试

- 每台新建 EC2 都要分配内网 IP，若分配公网 IP 才能用 SSH 登录
- 外网访问还需配置安全组开放目标端口

***

通过 Jenkins 持续部署到 EC2 实例

- 实现持续集成/部署（CI/CD）的完整能力，可用 Jenkins 通过 SSH Agent 插件在流水线自动连接 EC2 并执行 docker run 等操作
- Jenkinsfile 示例:
``groovy
stage("deploy") {
steps {
script {
echo 'deploying docker image to EC2...'
def dockerCmd = "docker run -p 3080:3080 -d \${IMAGE_NAME}"
sshagent(['ec2-server-key']) {
sh "ssh -o StrictHostKeyChecking=no ec2-user@EC2_IP \${dockerCmd}"
}
}
}
}


***

基础设施即代码（IaC）预览

- Terraform 用声明式代码描述目标基础设施，一次写成反复复用，比手动配置高效安全。
- Terraform 的实际流程包括先编写 tf 文件，执行 terraform plan/apply 一步完成环境全量部署/变更/销毁。

***

AWS 容器服务预览

- ECR：企业自动化镜像仓库
- ECS：AWS 原生容器编排
- EKS：AWS 托管 Kubernetes 服务，用于大规模容器集群。

***

最佳实践

- IAM：每人独立密钥，不共用，400 权限，定期轮换。
- VPC：细化隔离，安全组/NACL 配置最小权限原则，禁用 root 私钥外泄。
- EC2：密钥仅存于 .ssh/ 目录下，妥善保护。全员自建 Key，生产绝不共用。
- 官方文档链接，建议持续参考最新安全、VPC、EC2 最佳实践指南。
