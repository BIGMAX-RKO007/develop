# 15.1-Ansible-Checklist.pdf

以下是《14.2 Automation Handout.pdf》的详细中文翻译：

***

**用 Python 自动化运维管理（以 AWS 为例）**

***

**自动化 \& 运维目标**

- 自动化基础设施创建（EC2/EKS 资源都可通过 Terraform 实现自动一键部署）
- 用 Python 自动化重复性维护任务，如：
    - 定期备份（快照）
    - 定期清理（如旧快照、过期资源）
    - 自动管理和配置已存在服务
    - 健康检查、监控告警（自愈）
- 在拥有大量（上百/上千）服务器的大型企业环境，这些自动化脚本可大幅节省运维人力和响应时间

***

**Boto3 — AWS 官方 Python 开发包**

- “库”或“包”就是可复用的代码工具/Boto3 专门用于自动创建与管理 AWS 资源（EC2, S3, EKS 等）
- 支持面向对象（resource）和低级 API（client）两种用法

```python
ec2_client = boto3.client('ec2', region_name="eu-central-1")
ec2_resource = boto3.resource('ec2', region_name="eu-central-1")
```

- 需先在 `~/.aws/credentials` 和 `~/.aws/config` 配置好认证信息
- 各云厂商有专用 SDK（Azure/Google Cloud 需要各自库）

***

**Terraform vs. Python 自动编排区别**

- Terraform
    - 有状态感知，能追踪当前和目标环境差异，并自动推算需要增、删、改哪些资源
    - 幂等（多次 apply 总得到一致结果，自动自愈）
    - 只需声明“目标”，具体步骤自动推演
- Python
    - 无自带状态感知，脚本只做自己定义的过程（每次执行对环境变化不感知）
    - 非幂等，动作重复问题需自己处理
    - 灵活度高，可任意组合多处逻辑、判断、手动编写复杂控制

***

**自动化实践任务拆解**

1. **EC2 状态检查**
    - 自动脚本遍历所有实例，输出当前运行/终止等状态与健康检查。
    - 使用调度库可实现周期性自动检查（如 schedule.every(5).seconds.do(...) 配合 while True 循环 run_pending）。
2. **批量标签管理**
    - 目标：为所有实例自动打上规范环境标签（如 environment=dev/production），支持多 region/多环境一体化自动管理。
3. **批量查询 EKS 集群信息**
    - 数十/上百集群的信息自动输出（如状态、endpoint、K8s 版本等），用于巡检和批量配置。
4. **数据卷备份/快照/恢复/清理**
    - 自动为每个 EC2 挂载卷做定时快照（可按 region/环境拆分，支持 schedule+python 调度）。
    - 自动定期清理历史快照，只保留最新 2 个，确保成本控制。
    - 快速故障恢复——指定目标快照/卷，自动创建新卷并挂载回实例，一键恢复。
5. **网站监控与自愈**
    - 用 Python requests 定时检测网站/接口健康，若异常自动邮件告警。
    - 自愈动作：远程重启容器（Docker）、自动 reboot 云服务器、调用云 API 触发弹性伸缩。
    - 可结合 Linode 或 AWS 云 API 扩展跨云多平台自愈/运维场景。

***

**异常和错误处理机制**

- 所有自动化运维脚本应严格做异常捕获、输出详细日志、支持自动重试/兜底（如快照失败后删除/重试）。
- 否则有可能导致数据丢失、状态错乱。
- Lambda：良好方案是有问题及时终止，清理现场后尝试重启；坏方案是放任失败，导致垃圾资源堆积。

***

**状态管理与幂等性重要性**

- Terraform 自动管理资源状态 \& 幂等，业务流程简洁、易于团队协作。
- Python 需手动控制状态，适用运维细节/灵活判断/人控计划任务，但大批量云资源建议用 IaC/DevOps 工具（如 Terraform/Ansible）代替。
