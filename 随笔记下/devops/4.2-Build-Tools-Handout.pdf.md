# 4.2-Build-Tools-Handout.pdf

以下是《4.2 Build Tools Handout.pdf》的详细中文翻译：

***

构建工具与包管理器

构建产物（artifact）

- 包含应用代码及其所有依赖。
- 应用需部署到生产服务器时，要将代码打包成一个可移动的文件（产物），也称“编译/构建代码”。
- 这正是构建工具或包管理器的用途。
- 产物包括应用本身及全部依赖项。

***

“构建工具/包管理器”是什么？

- 编译代码
- 压缩代码
- 将成百上千文件打包成单一文件
- 需要存储构建产物以做多次部署、备份等。
- 产物仓库分别用于开发、测试、生产。

***

不同语言的产物文件各不相同

- 如 Java Archive (JAR)、Web Archive (WAR)。
- Spring、日期库、PDF 处理等功能通常以不同的库依赖加入并随产物一起打包。

***

本模块覆盖的构建工具：

- Java：Gradle 和 Maven
- JavaScript：npm

***

本模块需安装的技术和项目：

- 技术：Java Gradle 应用、Java Maven 应用、Node.js 应用。
- 项目：上述三种项目都需实际安装与配置。

***

项目安装设置流程

- 下载 IntelliJ 代码编辑器
- 安装操作系统包管理器（如 Mac 的 Homebrew）
- 安装 Java, Maven, Node, npm
- 克隆 Git 项目并用 IntelliJ 打开
- 分别配置 Java-Maven 项目和 Java-Gradle 项目

***

用构建工具构建产物

- 用命令行工具和命令进行依赖安装、代码编译、压缩打包
- Gradle 使用 Groovy 配置，Maven 用 XML 配置。
- Maven 构建产物存于 target 目录，Gradle 存于 build 目录。

***

开发阶段本地构建工具用途

- 开发应用时本地需用构建工具，进行测试、启动应用、管理依赖。
- 依赖文件（build.gradle、pom.xml）中列出所需库，需新库时只需加进配置表。
- 所有 Java 库可在 Maven 中央仓库查找，指定名称和版本后自动下载到本地。
- 如需 ElasticSearch 库，只要配置依赖并自动下载安装。

***

运行 Java 应用

- 本地定位 jar 文件，用 java -jar <jar 文件名> 运行。
- 部署时，拷贝 jar 文件到服务器再执行 java -jar 命令。

***

构建 JavaScript 应用 - 1

- JS 应用的产物通常是 zip 或 tar 包，没有特殊产物类型。
- JS 世界主用包管理器（npm、yarn），而不是专门的构建工具。
- package.json 记录所有依赖，npm/yarn 安装依赖但不转译代码。

***

npm 常用命令

- npm install：安装依赖
- npm start：启动应用
- npm stop：停止应用
- npm test：运行测试
- npm publish：发布产物

***

JS 应用部署流程

- 将 zip/tar 包拷贝到服务器，解压后安装依赖再启动应用。
- 产物包只含应用代码，不含所有依赖。

***

JS 灵活性

- 前端与后端代码可单独打包，或合并为一个产物。JS 工具链远较 Java 灵活且不标准化。
- 如多语言项目，前端用 React.js，后端用 Java/Node.js/Python 等。
- 前后端可各自拥有独立的 package.json 文件。

***

前端打包

- React 代码需转译为浏览器兼容格式，还要压缩/混淆。
- 如用 webpack 实现转译、压缩、打包。
- 浏览器各版本支持有限，如 React JSX 需转译为标准 JS。

***

其他语言包管理器/构建器

- Java：maven/gradle
- JS：npm/yarn/webpack
- Python：pip
- C/C++：conan
- C\#：NuGet
- Golang：dep
- Ruby：RubyGems

***

构建包流程通用模式

- 所有工具都有依赖配置文件、包仓库、命令行工具实现安装、编译和发布。
- 无论 build.gradle、pom.xml、package.json、test、start、build、publish，都存在大致同样流程。
- 打包产物上传到产物仓库，便于后续下载与部署。可用 curl/wget 获取。

***

为什么产物不直接保存而用 Docker？

- 不手动存 jar/zip，而是用 Docker 统一打包，更简洁易用。
- Docker 镜像本身就是一种产物，是所有“产物”类型的通用替代。
- 镜像内可直接执行依赖安装和应用启动等命令。

***

构建工具与 Docker

- 构建 Docker 镜像无需关心多种产物类型（Jar、War、Zip），只需统一构建镜像并按需分发。
- Docker 镜像即是一种产物，可解决所有打包和分发环节。

***

注意：应用本身仍需先构建！Docker 仅是打包和分发方便。详细用法后续模块介绍。

***

为什么 DevOps 工程师需要懂构建工具？

- 你能协助开发者构建应用，因你清楚部署服务器的运行环境。
- 你要配置自动化构建工具或 CI/CD 流水线，实现无人值守自动安装依赖、运行测试、构建/打包、发布产物。
- 具体命令参考：npm install, npm test, npm run build, npm publish, mvn test, mvn install
