# 15.2-Ansible-Handout.pdf

以下是《15.2 Ansible Handout.pdf》的详细中文翻译，涵盖 Ansible 配置管理与自动化部署的核心内容和最佳实践：

***

**Ansible 配置管理基础**

- Ansible 用于重复性任务自动化，如系统配置、软件部署、高级 IT 编排。
- 典型场景：批量升级/备份/用户创建/权限分配/批量重启等。
- 适合一套配置推送到多台服务器，无需逐台 SSH，只需本地一条命令，全局同步。

***

**Ansible 优势**

- 配置安装与部署流程写在一个 YAML 文件中，可多环境复用，极大提升可靠性与一致性。
- 支持所有主流 OS 与云平台，自动适配。
- 配置用 YAML，人类可读，无需学习新语法。
- 无需在被控端部署 agent，仅用 SSH 即可连接。
- “声明式+无状态”方式避免手工操作错误。

***

**Ansible 模块与 Playbook 架构**

- 模块是可重用且独立的功能单元（如安装 nginx、管理用户、操作文件、数据库等），所有动作都以模块为核心。
- Playbook 集成多个模块，按顺序自动执行，实现业务流程协同。
- Playbook 结构举例：

```yaml
- hosts: webservers
  remote_user: root
  tasks:
    - name: 创建 nginx 目录
      file:
        path: /path/to/nginx/dir
        state: directory
    - name: 安装 nginx
      yum:
        name: nginx
        state: latest
    - name: 启动 nginx
      service:
        name: nginx
        state: started
```


***

**Playbook 分析**

- 一个 Playbook 可有多个 play，每个 play 针对不同主机/场景，描述不同的编排目标和步骤。
- 每个 task 执行一个具体模块，顶层 hosts 字段指定作用服务器，remote_user 定义用哪个用户执行。

***

**Docker 与主机混合场景**

- Playbook 可跨容器、虚拟机、物理机等任意资源协同，既能装包也能动态配置主机与环境（比单纯 Dockerfile 灵活得多）。

***

**Ansible Tower**

- 企业级图形化管理方案，实现权限可控、任务模板化、团队协作与状态全生命周期追溯。

***

**模块、插件与 Ansible Galaxy**

- 模块覆盖所有主流基础设施/服务：云平台、数据库、文件、网络、消息、监控等，支持社区自定义扩展。
- 通过 Ansible Galaxy 查找和安装更多集合（类似 Terraform Registry、PyPI），实现自动化快速集成。
- Ansible Collections 支持模块/插件/角色一体的复合打包，便于复用和分享。

***

**变量管理**

- 变量可令 Playbook 参数化，一套脚本多环境灵活切换，建议 vars_file 单独管理所有敏感/差异参数。
- 引用变量用 `{{ var_name }}`；有时需整体用引号避免 YAML 语法冲突。
- 变量命名规则：字母、数字、下划线开头，不能用保留字。

***

**配置与项目结构最佳实践**

- 每个项目都应有单独 hosts 清单 + ansible.cfg 配置；所有 Playbook 与变量均纳入 Git 管理，实现“基础设施即代码”。
- Ad-hoc 命令方便临时批量操作；正式协同建议全部写到项目清单与 Playbook 脚本内。

***

**与 Terraform 等工具配合**

- Terraform 负责纯资源编排（如 EC2 实例、集群等的创建/删除），Ansible 负责服务器配置应用部署。
- 配合使用时，推荐 Terraform output 输出 IP/配置（自动同步到 Ansible hosts/inventory）；用 local_exec 執行 Playbook 完成自动化链路对接。
- 动态 inventory（如 AWS EC2 插件）可自动发现在云端弹性变化的主机，无需手动维护 IP 清单，支持标签分组。

***

**Ansible Roles（角色）**

- 角色是可复用、分层管理的大型功能合集。每个 role 有独立 tasks、handlers、vars、defaults、files、templates、meta 目录，便于大型项目结构化拆解和复用。
- 可通过 Ansible Galaxy 或 Git 高速拉取公共角色/最佳实践包。

***

**典型项目/集成场景举例**

- **Nexus自动化部署**：一条 Playbook 安装/运行 Nexus 并指定用户验证应用可用
- **Node 应用部署**：全部安装/解包/启动脚本及可用性校验自动一体化
- **Docker/K8s一体化**：支持主机、Docker 容器、K8s 资源混管，支持多环境批量自动化

***

**Jenkins 集成**

- 配置 Jenkins Job/Pipeline，自动触发 Ansible Playbook 本地或远程部署，打通 CI/CD 全链路。

***

**官方最佳实践推荐**

- 业务建议每一配置/主机/变量/角色独立拆分，严格 Git 管理。
- 复杂任务复用现有高质量角色/集合，变更合并与上线全自动化。
- 参考红帽/Ansible 官方文档和最佳实践文档进行项目结构设计与团队协作。
