# 继续

继续为《7.2 Docker Handout.pdf》详细翻译（本部分涵盖 Docker 架构、常用命令、端口映射、Compose、Dockerfile、仓库、卷持久化与最佳实践等）：

***

Docker 架构组件

- Pull 镜像
- 管理镜像与容器
- Docker 引擎（Docker Engine）：核心服务，维护镜像、容器生命周期
- Docker CLI：命令行接口，通过命令与 Docker Server 交互，可用 API 调用
- Docker Desktop：Mac/Windows 上的完整客户端
- Linux 上原生支持 Docker

***

Docker 主要命令

- docker run：基于镜像创建新容器
- docker pull：从仓库拉取镜像
- docker start/stop：启动/停止容器
- docker images：列出本地镜像
- docker ps/ps -a：列出运行中/全部（含已退出）容器
- docker logs：查看容器日志
- docker exec -it：新建终端并进入容器

***

端口映射

- 主机与容器如果有端口冲突，需做端口映射。
- 例：docker run -p 8080:8080 {image} 左侧为主机端口，右侧为容器端口
- 可运行多个容器，只要主机端口不冲突即可。
- 生产部署时常见 host:port --> container:port（外部流量映射进应用）

***

Docker 工作流简述

1. 代码提交至 Git
2. CI 服务器构建生成镜像，推送至公有/私有仓库（如 DockerHub, AWS ECR）
3. 部署服务器从仓库拉取镜像并运行

***

Docker Compose 多容器编排

- Docker Compose 用 YAML 文件集中定义多个服务的协同运行，可替代繁琐的 docker run 命令。
- 每个服务单独配置镜像、端口、环境变量、网络。Compose 会自动创建独立网络实现容器间通信。
- 例 docker-compose.yaml 配置多个服务，运行 docker-compose up 即可一键启动所有服务。

***

Dockerfile 原理与常用指令

- Dockerfile 是描述如何构建自定义镜像的文本文件。
- 常用命令：FROM（基础镜像）、ENV（定义环境变量）、RUN（执行构建时命令）、COPY（拷贝文件）、CMD（容器启动命令）
- 每条指令产生一层镜像，最终组合为一镜像文件。
- 示例：基于 node, 设置环境变量、创建目录、拷贝代码、启动服务。
- Dockerfile 可供 CI/CD 流水线自动构建产物。

***

镜像仓库与企业私有仓库

- 默认公有仓库为 DockerHub，公司一般采用私有仓库（如 AWS ECR、Azure Container Registry）
- 私有仓库需要认证登录，推送/拉取镜像须带仓库域名前缀
- 镜像标签格式：registryDomain/imageName:tag
- 生产环境二进制发布与镜像托管分离，部署时自动拉取指定版本镜像

***

容器数据持久化 - Docker Volumes 卷

- 数据默认存于容器虚拟文件系统，销毁容器时数据即丢失。
- 持久化需用 Volume 卷，把主机文件夹挂载进容器。
- docker run -v /home/mount/data:/var/lib/mysql/data 实现主机-容器文件映射
- 卷分为 Host 卷、匿名卷、命名卷，生产推荐用命名卷。
- Compose 配置 volume 可复用同一数据目录实现持久化，如 db-data:/var/lib/mysql/data

***

Docker 最佳实践

- 安全性：只用官方/可信图片做基础镜像，防止恶意代码。
- 安全性：生产明确用具体版本号，勿用 latest，防止潜在变故。
- 尺寸优化：尽可能选 alpine 等极简系统基础镜像。
- 尺寸优化：用 .dockerignore 排除无关文件，采用多阶段构建分离开发与运行产物。
- 权限建议：生产环境只用最小化权限非 root 用户运行。
- 敏感信息绝不写入镜像，环境变量单独注入。
- 定期扫描镜像漏洞，及时更新。
