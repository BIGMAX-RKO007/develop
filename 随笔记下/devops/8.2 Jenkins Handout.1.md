# 继续

继续《8.2 Jenkins Handout.pdf》的详细中文翻译，涵盖 Freestyle/Pipeline/多分支流水线、Jenkinsfile 结构、共享库、凭据管理、自动触发、版本自动递增与最佳实践等：

***

Jenkins Job 类型（项目类型）

- Freestyle Job（自由风格任务）：适用于单一任务或简单构建流程，全部配置通过 UI 完成，功能有限。
- Pipeline Job（流水线任务）：适合更复杂 CI/CD 场景，可拆分成多个阶段（stage），既支持界面配置也支持脚本（重点推行“Pipeline as Code”）。
- Multi-configuration Job（多配置任务）：适合需要在多种环境/参数下批量执行的任务。
- Multibranch Pipeline Job：自动检测 Git 仓库的所有分支，为每个分支自动创建并执行独立 Pipeline，可各自用不同 Jenkinsfile。
- Organization Folder/Folder：用于项目大规模归类和权限隔离。

***

Jenkinsfile 结构与写法

- Jenkinsfile 用于声明 Pipeline，存 Git 库，支持脚本式和声明式两种。
    - 声明式语法（Declarative）：格式固定，便于上手。
    - 脚本式语法（Scripted）：Groovy 脚本，功能极强。
- 结构核心：pipeline（顶级）、agent（执行位置）、stages（多个阶段）、stage/steps（工作内容），支持 post 控制逻辑和环境变量等特性。
- 支持条件、参数化、外部 Groovy 文件复用、内置环境变量（如 BRANCH_NAME、BUILD_NUMBER）。

***

参数化与外部 Groovy 脚本复用

- Pipeline 支持添加参数（如版本号选择、布尔开关等），提升复用/适应性。
- 可引用外部 Groovy 脚本（script.groovy），集中实现重复逻辑，协同维护。

***

Jenkins 多分支流水线（Multibranch Pipeline）

- 自动识别 Git 仓库所有分支并为每分支建立独立流水线，各自 Jenkinsfile 灵活定制。
- 无需手动新建 Pipeline 项目，只要分支存在即可自动发现并运行。
- 推荐用于微服务团队和多环境（dev/feature/main）自治管理。

***

凭据管理（Credentials）

- 流水线上各环节需用密钥、密码、令牌（如拉代码、上传镜像、SSH 远程等）。
- 可存储：用户名密码、SSH 密钥、Secret 文件、API Token、证书等，支持插件拓展。
- 凭据分为系统级与全局级，可分层授权按需引用，安全且灵活。
- 界面配置与流水线代码两种引入方式，推荐权限最小化原则和定期轮换。

***

Jenkins 共享库（Shared Library）

- 可将通用脚本逻辑封装为独立 Git 库，并全球化注册到 Jenkins 下所有流水线。
- 巨型微服务、跨团队复用场景下高效且规范。
- 配置方法：注册全局 Shared Library（git地址+凭据+分支），在 Jenkinsfile 头部 @Library('xxx@branch') 即可导入。
- 结构包括 vars（通用函数）、src（复杂工具封装）、resources（脚本模板等），易于工程化管理。

***

自动触发机制与 Webhook

- 三种触发模式：
    - 自动触发（如代码仓库 Webhook，推送即执行）
    - 人工手动触发
    - 定时触发（可设定周期性任务、cron 表达式）
- 推荐代码库和 Jenkins 配置 Webhook，实现每次 push/merge 自动执行全集流程。
- 配置：Git 仓库填写 webhook url 并配 Token，Jenkins Multibranch 配置观察触发 Token，即可打通闭环。

***

版本号管理与自动递增

- 各包/项目配置文件会自带 version 字段（如 Maven pom.xml、Gradle build.gradle、JS package.json）。
- 版本规则：主版本.次版本.修订号-后缀（如 1.2.0-SNAPSHOT）。主=大变更，次=兼容增强，修订=补丁。-SNAPSHOT=开发版、alpha=测试版等
- 推荐流水线集成自动递增、自动提交版本号变更，如 maven-helper、npm 相关命令等工具统筹管理。

***

Jenkinsfile 最佳实践

- “Pipeline as Code”：Jenkinsfile 入库，历史可回溯，团队协作更透明。
- stage 块内做全部非初始化工作，便于可视化/调试。
- 文件头加 \#!/usr/bin/env groovy，便于编辑器和 GitHub 语法高亮。
- input 步骤一定用 timeout 包裹，防止管道死等。
- 自动化版本管理、脚本逻辑共用、敏感信息分离。
- 详细指引见 https://www.lambdatest.com/blog/jenkins-best-practices/
