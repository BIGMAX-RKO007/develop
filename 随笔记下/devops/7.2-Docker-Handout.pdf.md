# 7.2-Docker-Handout.pdf

以下是《7.2 Docker Handout.pdf》的详细中文翻译（第一部分，涵盖 Docker 基本概念、原理及应用流程对比）：

***

容器与 Docker 简介

什么是 Docker？

- Docker 是一个开源容器化平台，允许开发者将应用包装成容器。
- 容器技术在 Docker 出现前就已经存在，是 Docker 让容器流行起来。

什么是容器？

- 容器是一种将应用与其全部依赖和配置一起封装打包的方式。
- 它是一种便于开发、交付与部署的可移植、标准化产物。
- 大大提高开发与部署效率。

容器产物的托管

- 存储于容器仓库，可为公有或私有。
- 公有仓库代表：DockerHub。

***

应用开发——容器化前后对比

- 容器化前:
    - 不同操作系统环境安装流程各异
    - 许多操作步骤易出错
- 容器化后:
    - 每个应用有自己的隔离环境和配置
    - 一条命令即可完成部署
    - 轻松运行不同版本的同一应用

***

应用部署——容器化前后对比

- 容器化前:
    - 服务器需做环境配置
    - 开发与运维需要配合完成应用的整体打包
    - 易出现依赖版本冲突
- 容器化后:
    - 服务器只需安装容器运行环境，无需单独做额外配置
    - 部署流程可文本化、标准化
    - 开发、运维间误解减少

***

Docker = 最流行的容器技术

- 类似产品还有其他，比如 podman、containerd、rkt（但 Docker 最主流）

***

镜像与容器的关系

镜像

- 实际的包（静态产物）
- 不是运行状态，由若干层组成，一般以 Linux 基础镜像为底，再叠加应用自有部分
- 可在各平台间移动

容器

- 运行时状态，从镜像启动后即进入“容器”状态
- 有独立运行环境、虚拟文件系统、端口绑定
- 实际承载服务器上的应用运行

***

容器（Docker） vs 虚拟机（VM）

- 两者都属于虚拟化工具
- 虚拟机是在物理硬件层抽象，每台包含完整操作系统
- 容器是在应用层抽象，多个容器共享主机系统内核
- 镜像体积远小于虚拟机
- 启动/运行速度远快于虚拟机
- 虚拟机可跨 OS 互跑容器有限制（比如 Linux 容器不能直接在 Windows 上跑，但 Docker Desktop 可实现）

什么是 Docker？

- Docker 是一个开源的容器化平台，能让开发者将应用打包进容器。
- 容器在 Docker 出现前就已存在，是 Docker 推动了其普及。

什么是容器？

- 容器是一种将应用和所有依赖及配置一起打包的方法。
- 它是一种为开发、分发与部署而设计的可移植、标准化产物。
- 提升了开发与部署效率。

容器产物的托管方式

- 托管在容器仓库（容器仓储），可以是私有或公有仓库。
- DockerHub 是 Docker 的公有仓库代表。

应用开发——有无 Docker 之比较

- 无容器前：
    - 每个操作系统下安装过程不同，容易出现各种问题
- 有容器后：
    - 应用有自己独立的隔离环境和配置
    - 安装部署只需一条命令
    - 可以轻松运行多个版本或多个实例

应用部署——有无 Docker 之比较

- 无容器前：
    - 服务端需要进行复杂环境配置
    - 开发和运维需协作打包应用
    - 常出现依赖/版本冲突
- 有容器后：
    - 只需在服务器上安装容器运行环境
    - 调度与维护变简单，流程可标准化

Docker = 最流行容器化技术

- 市场上还有其他容器平台，但 Docker 占主导地位。

镜像 (Image) 与容器 (Container) 的区别

- 镜像是静态“包”或工件，仅作为分发单位由多个层组成，底层多基于 Linux 镜像。
- 容器是镜像的运行时，代表了实际运行环境和应用。
- 容器有虚拟文件系统及端口映射，承载宿主机上的应用。

容器和虚拟机对比

- 二者都是虚拟化技术。
- 虚拟机在硬件层抽象，每个 VM 都有完整操作系统。
- 容器抽象应用层，不同容器共享宿主内核。
- 容器镜像更小、更快、可弹性扩缩、更易管理。
- 虚拟机 OS 可混搭但 Linux 容器不能直接原生在 Windows 跑（可用 Docker Desktop 实现间接兼容）。
