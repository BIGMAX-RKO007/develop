# 11.1-K8s-on-AWS-Handout.pdf

以下是《11.1 K8s on AWS Handout.pdf》的详细中文翻译：

***

在 AWS 上部署 Kubernetes（K8s）核心知识大纲

***

AWS 的容器相关服务

- 私有 Docker 镜像仓库 —— Elastic Container Registry（ECR）
- 容器编排服务 —— Elastic Container Service（ECS）
- 托管 Kubernetes 服务 —— Elastic Kubernetes Service（EKS）

***

ECS 原理简介

- 控制平面（Control Plane）由 AWS 完全托管
- 计算资源位于 EC2 节点，所有节点注册至 ECS 进行统一编排和调度
- 每个 EC2 Node 实例需安装：
    - 1. 容器运行时（如 Docker）
    - 2. ECS Agent，用于和 ECS 控制平面通信

***

ECS 运行方式对比：EC2 与 AWS Fargate

- ECS on EC2：
    - 容器由 AWS 管理，但你需自主管理主机虚拟机（EC2）
    - 服务器全天计费
- ECS on Fargate：
    - 基础设施由 AWS 托管，按运算资源弹性计费
    - 自动按需扩缩，易于管理，纯“Serverless”

***

EKS - 完全托管的 Kubernetes 集群

- EKS 兼容开源 K8s API，支持原生各种 Helm Chart、社区组件，迁移可控。
- 区别 ECS：EKS 更开放，社区和企业级生态（Helm Chart 等）丰富，易于多平台迁移。

***

ECS vs EKS 核心差异

- ECS 控制平面免费；EKS 需另付集群控制平面费用
- EKS 直接兼容 K8s，云厂商迁移更容易
- ECS 更侧重 AWS 原生使用场景，支撑结构更简单

***

EKS 架构解读

- EKS 集群包括 当前托管的 K8s Control Plane 与你的 Worker Node 群组
- 控制平面高可用，横跨 3 个可用区（Availability Zones）
- Worker Node 有三种宿主方式：
    - EC2 实例 — 你自主管理
    - Node Group — AWS 半托管，批量自动维护
    - Fargate — 完全托管无服务器 Worker Node

***

EKS 集群创建高阶流程

1. 开通 EKS 集群（分配控制平面节点）
2. 新建 EC2 NodeGroup 作为 Worker（分配虚拟机组）
3. 将 NodeGroup 绑定至 EKS 集群
4. 部署你的容器化应用

***

EKS 集群创建详细步骤

1. 创建 EKS 专用 IAM 角色，赋权 AWS 自动创建相关底层服务资源
2. 新建 Worker Node VPC，按 AWS 最佳实践分 Public/Private 子网
3. 新建 EKS 集群，配置 kubectl 访问
4. 新建 Node Group（WorkerNode），分配 EC2 IAM 角色与权限
5. 配置自动弹性伸缩
6. 用 kubectl 部署工作负载（应用/服务/Job）

***

VPC 网络与权限

- EKS 需专用 VPC，需配置三可用区（基础设施高可用）
- Worker Node 与 Control Plane 的通信需配置好 VPC 路由和安全组
- 最佳实践：公有子网部署负载均衡，私有子网运行业务 Pod 与数据库
- 通过 IAM Role，K8s 控制平面可以变更 VPC 配置实施自动化扩容和负载分发。

***

自动命令行工具 eksctl

- eksctl 是 AWS 推荐的命令行工具，自动帮你创建集群和所有相关资源
- 只需一行命令就能初始化完整集群及安全配置
- 也可用 Terraform（IaC）模块批量声明式配置，与企业级代码管理集成

***

K8s Worker 权限与流程

- Worker Node 内需装 Kubelet（Pod 编排与 AWS 云服务通信核心进程）、runtime、k-proxy
- NodeGroup 角色需授权 Kubernetes 自动调用 AWS API 管理底层资源

***

Amazon Elastic Container Registry (ECR) 用法

- 私有容器镜像仓库，适用 ECS/EKS
- 自动集成 IAM 权限及 AWS 生态
- 支持镜像版本、标签管理、访问权限限制、镜像安全扫描
- 自动推送/拉取镜像至各云区域工作负载，无需额外复杂配置
- ECR 支持和 Jenkins/EKS/ECS 集成交付流水线

***

Jenkins 持续集成部署到 EKS 最佳实践

1. 给 Jenkins 新建 AWS IAM 专用账号，只分配必要权限
2. 在 Jenkins 容器内装好 kubectl、aws-iam-authenticator 工具
3. 生成 kubeconfig 文件，配置 EKS 集群访问
4. 通过 Jenkins 配置 AWS 相关凭据及 K8s 访问信息
5. Jenkinsfile 流水线脚本内添加到 EKS 的登录与部署命令，完成自动化交付

- 认证方式须同时通过 AWS 和 Kubernetes

***

生产环境安全与运维最佳实践

- VPC 建议公私网分离（安全、隔离）
- K8s Secret 借助 AWS KMS 做信封加密，增强敏感信息保护
- 强烈建议长期参考 AWS 官方 EKS 最佳实践：https://aws.github.io/aws-eks-best-practices/
- 所有建议源于 AWS 实际生产环境+K8s 官方认证团队总结
